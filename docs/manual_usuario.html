Explicaciones de IA que se adaptan a quien las lee

Profile XAI genera explicaciones interpretables para modelos de clasificación de caja negra, y las redacta en tres registros distintos según quién las necesite: quien construyó el modelo, quien conoce el dominio, o quien solo quiere entender la decisión.

SHAP·LIME·Anchor Vertex AI RAG Engine + Gemini 2.5 Cloud Run · us-central1
00 — Resumen

¿Qué hace la herramienta?

Sube un modelo entrenado, el dataset con el que fue entrenado, y documentación de referencia. Profile XAI convierte el modelo a un formato agnóstico, calcula por qué tomó una decisión puntual con tres métodos de explicabilidad distintos, y redacta esa razón en lenguaje natural — ajustado al perfil de quien pregunta y respaldado por la base de conocimiento que subiste.

Motor XAI

Interpretabilidad agnóstica

SHAP, LIME y Anchor calculados sobre el mismo modelo convertido a ONNX, sin importar si el original era scikit-learn o LightGBM.

Narrativa

Perfil adaptativo

La misma predicción se redacta distinto para un data scientist, un experto de dominio o alguien sin formación técnica.

Contexto

Chat con RAG

Preguntas de seguimiento respondidas con Vertex AI RAG Engine sobre la documentación que subiste, no solo con el modelo.

01 — Requisitos

Antes de empezar

Cada sesión de análisis necesita tres archivos. La herramienta los valida y, si el modelo es un pickle, lo escanea en busca de código malicioso antes de aceptarlo.

Dataset de referencia.xlsx .csvMismas columnas usadas para entrenar; se usa como fondo estadístico para SHAP/LIME.
i

La primera conversión de un modelo con una combinación nueva de versiones (scikit-learn / LightGBM) construye una imagen de conversión desde cero y puede tomar 3–5 minutos. Las siguientes conversiones con esa misma combinación reutilizan la imagen y toman segundos.

02 — Caso de estudio

Dictámenes de licencias médicas, SUSESO

Este manual usa un caso real de referencia para mostrar la herramienta en acción: el modelo predictivo desarrollado para la Superintendencia de Seguridad Social de Chile (licitación 1607-28-LE23).

base_de_conocimiento — dictamenes_suseso.txt

La SUSESO resuelve reclamaciones de trabajadores cuya licencia médica fue rechazada por una Isapre o el COMPIN. Recibe ~150.000 reclamaciones al año, creciendo 10% anual, con 40 días promedio de resolución. El modelo predice si el dictamen final será ACOGIDA (se revierte el rechazo) o NO ACOGIDA (se mantiene), a partir de los datos disponibles al momento del ingreso — antes de que un equipo médico revise el caso.

Usaremos este modelo para recorrer el flujo completo: subir los tres archivos, convertir el modelo, generar una explicación y conversar con la base de conocimiento.

03 — Flujo de uso

De la subida de archivos a la explicación

Ocho pasos, en orden. Cada uno depende del anterior — la herramienta no deja avanzar si falta un archivo o una conversión.

Ingresa a la herramienta

Inicia sesión con Google o continúa como invitado — la autenticación real aún no es obligatoria.

Elige los perfiles disponibles para esta sesión

Puedes habilitar uno o los tres; se puede cambiar más adelante desde la vista de explicación.

DS

Especialista en IA

Detalles técnicos, métricas y salidas directas de los explicadores.

DE

Experto en el Dominio

Lenguaje natural con contexto especializado desde la base de conocimiento.

UG

Usuario General

Lenguaje accesible, ejemplos claros y conclusiones simplificadas.

Sube los tres archivos

Base de conocimiento, modelo y dataset de referencia. La barra de progreso marca 3/3 listos cuando puedes continuar.

Convierte el modelo

La herramienta detecta el framework (sklearn, LightGBM o mixto) y lo convierte a ONNX en un entorno aislado. Al terminar, muestra las clases que el modelo puede predecir.

Nombra esas clases

El modelo devuelve etiquetas como 0 / 1; aquí les das el nombre real — p. ej. "NO ACOGIDA (rechazo mantenido)".

Completa o sortea una instancia

Llena el formulario a mano, o pide un caso aleatorio del dataset de referencia para probar rápido.

Lee la explicación

Predicción, confianza, y una narrativa redactada para el perfil activo — con el detalle técnico disponible en pestañas aparte.

Pregunta al chat

Cualquier duda de seguimiento se responde citando la base de conocimiento, en el mismo registro del perfil activo.

04 — Cómo leer la explicación

Un ejemplo real: por qué se rechazó este caso

Esta es una instancia real del caso SUSESO, explicada por el motor SHAP con el modelo LightGBM convertido — causa_rechazo: Falta_Antecedentes, patologia: Medica_General. El modelo predijo NO ACOGIDA con 79.24% de confianza.

SHAP

Contribución marginal

Cuánto empuja cada variable la predicción hacia una clase u otra, en unidades de log-odds. Positivo = hacia la clase predicha.

LIME

Aproximación local

Un modelo lineal simple ajustado solo alrededor de este caso — más fácil de leer, menos preciso lejos del punto.

Anchor

Regla suficiente

Condiciones mínimas que, si se cumplen, anclan siempre la misma predicción: causa_rechazo = Falta_Antecedentes ∧ patologia = Medica_General → NO ACOGIDA.

Preguntas de seguimiento

Cualquier duda sobre la explicación puede resolverse conversando — la respuesta combina el contexto de la explicación activa con lo indexado en Vertex AI RAG Engine desde tu base de conocimiento.

Pregunta

¿Por qué el departamento de cierre influye en el dictamen?

Respuesta

El departamento asignado puede reflejar la especialización o el tipo de casos que maneja habitualmente, lo que influye en la evaluación. Esto puede llevar a criterios de revisión específicos o a una interpretación particular de la normativa, afectando el dictamen final.

07 — Preguntas frecuentes

Antes de escribir soporte

La primera carga tarda varios segundos, ¿está caída la herramienta?

No — el backend escala a cero cuando nadie lo usa, para no consumir recursos en vano. La primera petición después de un rato de inactividad "despierta" la instancia; las siguientes son inmediatas.

Subí mi modelo y lo rechazó con un error de seguridad, ¿por qué?

Todo archivo .pkl pasa por un escaneo estático antes de cargarse, buscando código ejecutable incrustado. Si algo dispara la alerta, el archivo se descarta sin llegar a cargarse. Reexporta el modelo con joblib.dump desde un entorno limpio si esto ocurre.

¿Qué pasa si mi modelo mezcla scikit-learn y LightGBM?

Se soporta: el conversor detecta ambos frameworks dentro del mismo pipeline y arma un entorno de conversión con las versiones exactas de cada uno.

El chat respondió que el módulo no está disponible.

Esto ocurre si la base de conocimiento aún no terminó de indexarse en Vertex AI RAG Engine, o si esa sesión no subió ningún archivo de conocimiento. Vuelve al paso de configuración y confirma que el archivo quedó cargado.
