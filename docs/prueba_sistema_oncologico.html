05 — Hallazgos críticos corregidos durante esta prueba

Lo que esta prueba encontró antes de que lo encontrara un usuario real

Crítico

El frontend nunca enviaba la API key al backend

Desde que se activó autenticación por API key en el backend (sesión anterior), mock-api.ts nunca agregó el header X-API-Key a ninguna llamada. Resultado: cada acción de un usuario real —subir un archivo, generar una explicación, chatear— habría fallado con 401. La app estaba, en los hechos, completamente inutilizable en producción.

Fix

Header centralizado en un helper authHeaders() aplicado a los 11 fetch de la librería; la key se inyecta en build-time desde Secret Manager (mismo secreto que ya usa el backend), vía Cloud Build availableSecrets.

Crítico

Vertex AI RAG Engine no podía crear el corpus en us-central1

La creación del corpus fallaba silenciosamente en cada intento, desde el primer despliegue — el error quedaba atrapado por un except que solo escribía un logger.warning, nunca visible en la UI. El chat y las narrativas funcionaban igual, pero sin ningún contexto real de la base de conocimiento: respuestas plausibles pero no fundamentadas.

WARNING:app.main:RAG no pudo inicializarse: ('Failed in RagCorpus creation due to: ', InvalidArgument('For new projects, using Spanner mode with RAG Engine in us-central1, us-east1, and us-east4 is restricted to only allowlisted projects...'))
Fix

GCP_LOCATION (variable independiente de la región de Cloud Run) cambiada a us-west1, donde la creación de corpus sí está permitida — verificado con una llamada real antes de aplicar el cambio en producción.
